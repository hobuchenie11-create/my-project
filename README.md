# Копилка класса

Прототип мобильного приложения для учёта сборов родительского комитета: кто сдал, кто нет,
сколько собрано и до какого числа нужно сдать.

Один файл `index.html` — открывается с телефона, ставится на главный экран,
работает и без общей базы (тогда данные живут только на этом устройстве).

## Что умеет

**Две роли.** Без общей базы они переключаются в шапке — для примерки.
С общей базой роль назначает сервер по введённому секрету:

- **Казначей (администратор)** — отмечает, кто сдал, заводит сборы, суммы и даты начала,
  ведёт траты и список класса, копирует напоминание для чата. Казначеев может быть двое —
  у каждого свой пароль.
- **Родитель** — смотрит: свою сумму и статус, сроки, реквизиты для перевода с кнопкой
  «Копировать», на что потрачены деньги. Ничего не редактирует.

**Категории сборов** (нижнее меню):

| Вкладка | Поводы |
|---|---|
| Подарки детям | Новый год · 23 февраля · 8 марта |
| Подарки учителям | День рождения · День учителя · Новый год · 8 марта · Выпускной |
| Ремонт класса | Ремонт и оснащение |
| Питание детей | Питание (помесячно) |
| Фонд класса | Ежемесячный взнос — по сбору на каждый месяц |

**Фонд класса** устроен иначе, чем разовые сборы: взнос повторяется каждый месяц.
Месяцы переключаются чипсами вверху, показываются только заведённые.
Кнопка «Открыть следующий месяц» заводит новый месяц с той же суммой и сроком.
Сверху — блок **«Долги по фонду»**: кто за какие месяцы не сдал и сколько должен,
отсортированный по глубине долга, с копированием списка для чата.
Родитель на этой вкладке видит только свой долг и месяцы, за которые не сдал.

**Список класса** — 29 строк: 24 ученика и 5 свободных мест в запасе для новых.
Заполняется вставкой: скопировать фамилии из чата по одной в строке и нажать
«Вставить список одним махом» — пустые строки и лишние пробелы отбрасываются.
Кнопка «Начать с чистого листа» в настройках удаляет демо-примеры перед реальной работой.
Свободные места видны в каждом сборе и заполняются на вкладке «Список класса» (иконка ⚙).
Новый ученик сразу попадает во все расчёты.

**Сумму можно задать двумя способами** — переключатель «Как считаем сумму» в форме сбора:

- **С человека** — казначей вводит долю, приложение показывает итог по классу.
- **Общая сумма** — казначей вводит смету (например, 25 000 ₽ за жалюзи),
  она делится на число сдающих и округляется вверх до рубля; излишек от округления показан явно.

**Число сдающих задаёт казначей** — сдают не всегда все: на подарки мальчикам скидываются
родители девочек, кто-то не участвует. Поле «Сколько человек сдают» по умолчанию равно
числу учеников, но его можно поставить любым. Если в списке отметить родителя как «Не сдаёт»,
число сдающих уменьшится само, а в режиме общей суммы доля остальных пересчитается.

**История трат** — на что ушли собранные деньги. У каждого сбора своя касса:
собрано / потрачено / остаток. Траты добавляются внутри сбора (что, сколько, когда, кто оплатил),
общий экран «Касса класса» показывает все траты по месяцам и остаток. Родители видят историю,
но не могут её править — это и есть прозрачность, которой обычно не хватает в чатах.

**Предельный срок сдачи считается автоматически:** дата начала сбора + срок в днях.
Дата пересчитывается прямо в форме при вводе. На карточке показывается,
сколько дней осталось; за 3 дня до срока карточка становится янтарной,
после срока — розовой с числом дней просрочки.

**Итоги** — на каждом уровне: по сбору (сдали N из 29, собрано X из Y, процент),
по категории и по классу целиком на вкладке «Обзор».

**Реквизиты у каждого сбора свои** — ответственные меняются от праздника к празднику.
В сборе указываются кто собирает, телефон или карта и банк; родителю они показаны крупно
с кнопкой «Копировать» (номер копируется без пробелов и дефисов — сразу вставляется в банк)
и попадают в текст напоминания. В настройках есть реквизиты казначея по умолчанию:
они подставляются в новый сбор, но меняются в нём независимо от остальных.

## Общая база (Supabase)

Без неё данные живут только в браузере устройства. С ней казначей и родители видят одно и то же.

### Кто что может

| | Казначей (администратор) | Родитель |
|---|---|---|
| Отмечать «сдал / не сдал» | да | нет |
| Заводить сборы, суммы, даты начала | да | нет |
| Добавлять траты | да | нет |
| Править список класса и реквизиты | да | нет |
| Видеть суммы, сроки, статусы | да | да |
| Видеть реквизиты для перевода | да | да |
| Видеть, на что потрачено | да | да |

Казначеев может быть несколько — у каждого свой пароль, поэтому доступ одному
можно отозвать, не трогая другого.

### Установка

1. Создать бесплатный проект на supabase.com.
2. Открыть `supabase-schema.sql`, заменить строку `ЗАМЕНИТЕ-ЭТУ-СТРОКУ-НА-СВОЮ`
   на свой токен установки, выполнить файл в SQL Editor.
3. Project Settings → API → скопировать Project URL и ключ **anon public**.
4. В приложении: ⚙ → «Общая база» → вставить URL, ключ и токен, задать
   код класса (от 6 символов) и пароль казначея (от 8) → «Создать класс».
5. Скопировать ссылку и отправить в чат класса. Код сообщить отдельно.

### Защита от посторонних

Ключ `anon public` по замыслу Supabase открыт всем, поэтому защита сделана в самой базе,
а не в интерфейсе. Таблица закрыта полностью (RLS без политик, права отозваны),
работа идёт только через функции `class_*`.

- **Два вида секретов.** Код класса даёт только чтение, пароль казначея — чтение и запись.
  Роль назначает сервер и возвращает её приложению; родитель не может «переключиться
  в казначея» — запись отклонит база.
- **Создание классов закрыто токеном установки.** Без него посторонний с вашим ключом
  не заведёт класс в вашем проекте.
- **Смена кода.** Казначей меняет код класса в любой момент — все, кто знал старый,
  сразу теряют доступ.
- **Защита от перебора.** Пять неверных попыток за 15 минут — и неверные секреты
  перестают приниматься ещё на 15 минут.

Две тонкости этой защиты выяснились на испытаниях и учтены в схеме:

1. Функции не бросают исключение при неверном секрете, а возвращают признак `ok=false` —
   иначе Postgres откатывал бы транзакцию вместе со счётчиком попыток и защита
   не работала бы вовсе.
2. Верный секрет проверяется до блокировки и счётчик не трогает. Иначе, во-первых,
   опрос базы приложениями родителей обнулял бы счётчик подбирающему, а во-вторых,
   посторонний мог бы пятью неверными попытками закрыть вход всему классу.

Чего эта защита не даёт: у кого есть и ссылка, и код — тот внутри. Пароль казначея
разграничивает права по-настоящему, но сам класс защищён ровно настолько, насколько
узок круг знающих код.

### Как устроена синхронизация

Состояние класса — один JSON-документ в таблице `classes`. Запись идёт с проверкой версии:
если кто-то опередил, клиент забирает свежее состояние, накладывает на него *свои* правки
(трёхстороннее слияние по ученикам, сборам и тратам) и повторяет. Поэтому две одновременные
отметки по разным ученикам обе сохраняются. Приложение опрашивает базу раз в 7 секунд,
сначала дешёвой проверкой версии. Роль и выбранный ребёнок хранятся отдельно от общих
данных — иначе роль казначея уехала бы всем родителям.

## Где разместить

Приложение — один файл `index.html`, ему не нужен сервер приложений, только раздача статики.

**GitHub Pages** (бесплатно): Settings → Pages → Source: ветка с приложением, папка `/`.
Через минуту появится адрес вида `https://<логин>.github.io/<репозиторий>/`.
Публичной будет только страница — данные лежат в вашей Supabase и открываются
лишь по ссылке с кодом.

На телефоне страница открывается в браузере и ставится на главный экран
(«Поделиться → На экран "Домой"» в Safari, «⋮ → Установить приложение» в Chrome) —
появляется иконка, и приложение запускается на весь экран, как обычное.

## Данные

Без общей базы всё хранится в браузере устройства. Деньги через приложение не проходят
ни в каком режиме — это учётный инструмент. Кнопка «Скопировать отчёт» на вкладке «Список класса» выгружает
сводку по всем сборам текстом, «Напомнить» — список не сдавших для отправки в чат.
Сбросить к демо-примеру можно там же.
