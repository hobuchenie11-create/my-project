# DH OS — план следующих модулей

Документ описывает три модуля: **Задачи**, **Домовед** (ИИ-навигатор) и
**Новосёлы**. Все они подключаются к общему ядру — базе данных, куда уже
пишет модуль сбора показаний.

Принцип разграничения доступа:

| Кто | Что видит |
|-----|-----------|
| **Председатель** | Всё: задачи целиком, реестр, ведомости, настройки |
| **Совет дома** | Только итоговое информационное сообщение по задачам |
| **Жители** | Показания, Домовед, вкладка новосёла |

---

## Модуль 1. Задачи (только председатель)

### Что хранится

Таблица `tasks`:

| Поле | Назначение |
|------|-----------|
| `number` | Порядковый номер задачи |
| `title` | Короткий заголовок |
| `description` | Подробности (внутренние, Совету не показываются) |
| `category` | Текущий ремонт · Благоустройство · ЖКУ · Безопасность · Документы · Прочее |
| `priority` | Высокий · Обычный · Низкий |
| `status` | Новая · В работе · Ожидает · Выполнена · Отменена |
| `assignee` | Ответственный (человек или организация) |
| `due_date` | Срок |
| `apartment_id` | Квартира, если задача из обращения жителя |
| `source` | Обращение жителя · Решение собрания · Председатель |
| `created_at` / `updated_at` / `done_at` | Даты |

Таблица `task_events` — журнал: кто и когда менял статус, срок, ответственного.
Нужен, чтобы в спорной ситуации было видно историю.

### Что умеет (меню председателя в боте)

- **➕ Новая задача** — диалог: заголовок → категория → срок → ответственный.
- **📋 Мои задачи** — список с фильтром по статусу, просроченные сверху.
- **✏️ Изменить** — статус, срок, ответственный, комментарий.
- **📤 Сводка для Совета дома** — формирует и отправляет информационное
  сообщение (см. ниже).
- Напоминание председателю о задачах с истекающим сроком.

### Итоговое сообщение для Совета дома

Совет **не имеет доступа к вкладке** — он получает только сводку, которую вы
отправляете кнопкой (или по расписанию, раз в месяц). Внутренние описания и
комментарии в неё не попадают:

```
📋 Совет дома — сводка по задачам на 15.09.2026

🔧 В работе (3)
• Ремонт козырька 2-го подъезда — до 20.09, УК «Комфорт»
• Замена ламп в лифтовом холле — до 18.09, электрик
• Опиловка тополей у 1-го подъезда — до 30.09, подрядчик

⏳ Ожидают решения (2)
• Установка велопарковки — нужен бюджет
• Ремонт отмостки — ждём смету

✅ Выполнено за месяц (5)
• Поверка общедомового счётчика ГВС
• Ремонт двери 3-го подъезда
…

Вопросы — председателю.
```

### Годовой цикл (реализовано)

Регулярные задачи описаны шаблонами и создаются на каждый месяц сами.
В плане они идут по датам, а не по времени добавления:

| Срок | Задача | Напоминания с |
|------|--------|---------------|
| 2-5 | Выписка из банка по спецсчёту | 2 |
| до 7 | Абонентская плата за GSM-модуль | 5 |
| до 10 | Аренда за нежилое помещение (сумма + дата) | 1 |
| 5-10 | Разноска платежей и печать квитанций | 5 |
| до 18 | Коммунальные услуги по нежилому (сумма + дата) | 10, подсветка с 15 |
| 20-25 | Передача показаний ресурсникам | 20 |
| до 30 | Абонентская плата ОКС | 27 |

В коротком феврале срок «до 30» становится последним днём месяца.

### Правки в Excel возвращаются в базу

Файл годового плана — выгрузка из базы, а не сама база. Чтобы правки,
сделанные на компьютере, увидел бот, файл отправляется обратно:
**🗂 Задачи → 📥 Загрузить правки** (или `python -m excel.tasks_import файл`).

- Строки находятся по скрытому столбцу «ID» — его нельзя удалять.
- Переносятся: статус, суммы аренды и коммуналки, даты оплат, комментарий,
  срок; с листа «Мои задачи» — правки и новые строки (строка без «ID»
  становится новой задачей); с листа «Поверка приборов» — дата последней
  поверки, интервал, заводской номер.
- Пустая ячейка означает «не менять»: случайно стёртая ячейка не удаляет
  данные, очистка делается в боте.
- Непонятные значения не проглатываются — бот перечисляет их в ответе.

### Этапы

1. Таблицы `tasks` и `task_events` + миграция. ✅
2. Меню председателя: создание, список, смена статуса. ✅
3. Сводка для Совета дома (кнопка + опционально по расписанию). ✅
4. Обратная загрузка правок из Excel. ✅
5. Позже — та же вкладка в веб-кабинете, с телефона.

## Модуль 2. Домовед — ответы на частые вопросы

### Как устроен

Таблица `faq`: вопрос · ответ · категория · ключевые слова · вложение
(картинка/PDF) · активен да/нет.

Логика ответа:
1. Житель пишет вопрос Домоведу.
2. Бот ищет по ключевым словам и категории.
3. Нашёл — отвечает, при необходимости присылает картинку или файл.
4. **Не нашёл** — честно говорит «не знаю, передам председателю» и
   записывает вопрос в журнал `faq_gaps`.

Журнал ненайденного — главный механизм роста базы: раз в неделю вы смотрите,
о чём спрашивали, и дописываете ответы. База пополняется реальными вопросами
жителей, а не догадками.

### Что заливаем в базу знаний

**1. Показания и оплата**
- Когда передавать показания (15–19 число) и что будет, если позже.
- Как передавать: шаблоны для 1-2-комнатных и 3-комнатных, оба способа.
- Почему у трёхкомнатных отдельно кухня/санузел и сумма ГВС.
- Куда ещё можно передать: личный кабинет Росводоканала и ОЭК, при оплате квитанции.
- Где взять квитанцию, как и до какого числа оплатить.
- Счётчик: истёк срок поверки, сломался, заменили — что делать и кому сообщить.
- Почему пришёл перерасчёт / начисление по нормативу.

**2. Дом и территория**
- **Ворота**: как запрограммировать пульт (ваша инфографика), сколько пультов
  на квартиру, где получить, что делать если не работает.
- **Домофон**: как открыть, как добавить/заменить трубку, кому звонить при поломке.
- **Парковка**: правила, гостевые места, что делать с чужим авто.
- **Мусор**: график вывоза, куда крупногабарит, что нельзя бросать.
- **Подъезд**: график уборки, что делать при жалобе.
- **Лифт**: действия при остановке, телефон диспетчера.
- **Отопление**: когда включают, что делать если холодные батареи.
- **Вода**: плановые отключения, аварии, куда звонить.

**3. Организации и контакты**
- Обслуживающая (управляющая) организация: название, телефон, часы приёма, адрес.
- Аварийно-диспетчерская служба — круглосуточный телефон.
- Росводоканал: телефон, сайт, личный кабинет.
- ОЭК: телефон, сайт, личный кабинет.
- Председатель и Совет дома: как связаться, когда.
- Участковый, при необходимости.

**4. Документы**
- Выписка из ЕГРН: зачем нужна дому, как заказать (Госуслуги / МФЦ), куда прислать.
- Справки (о проживании, об отсутствии задолженности): где заказать.
- Протоколы общих собраний: где посмотреть.
- Правила проживания: полный текст.
- Как подать обращение председателю.

**5. Собрания и решения**
- Как проходят собрания, как проголосовать, где итоги.
- Как инициировать вопрос на повестку.

**6. Новосёлам** — краткие ответы со ссылкой на вкладку новосёла (модуль 3).

### Обкатка до публикации

1. **Собрать сырьё**: выгрузить реальные вопросы жителей из чата дома за
   последние месяцы — по ним видно, что спрашивают на самом деле.
2. **Наполнить** 30–50 пар «вопрос — ответ» по разделам выше.
3. **Тестовый режим**: Домовед отвечает **только председателю**. Вы задаёте
   вопросы «как житель» и проверяете формулировки.
4. **Пригласить 3–5 жителей** (например, Совет дома) — они спрашивают,
   мы смотрим журнал ненайденного и дополняем.
5. **Открыть всем** — только после того, как на типовые вопросы есть ответы.

Наполнение базы не требует сервера: это работа с текстами, её можно вести
параллельно с обкаткой показаний.

### Что нужно от вас

- Контакты организаций (обслуживающая, аварийная, ресурсники).
- Текст правил проживания.
- Инфографика по воротам.
- Порядок выдачи пультов и ключей.
- График вывоза мусора и уборки.

## Модуль 3. Вкладка для новосёлов

### Сценарий «Я новый житель»

Пошаговый диалог; на каждом шаге можно остановиться и вернуться позже.

1. **Приветствие** — коротко о доме, чате и Домоведе.
2. **Правила проживания** — текст + подтверждение «ознакомлен».
3. **Выписка из ЕГРН** — зачем нужна (подтверждение права собственности для
   реестра дома), как заказать (Госуслуги / МФЦ), куда прислать. Житель может
   прислать файл прямо в бот.
4. **Ворота** — инфографика по программированию пульта, сколько пультов
   положено, где получить.
5. **Домофон** — как работает, куда обращаться.
6. **Обслуживающая организация и ресурсники** — контакты, какие договоры
   нужно заключить, куда передавать показания.
7. **Автомобиль** — если есть, житель указывает госномер (для пропуска и
   парковки). Можно указать несколько.
8. **Показания счётчиков** — сроки и шаблоны (передаёт в модуль показаний).
9. **Готово** — итоговая памятка одним сообщением.

### Что добавляем в базу

К карточке квартиры/жителя:

| Поле | Назначение |
|------|-----------|
| `move_in_date` | Дата заселения |
| `egrn_status` | Выписка: не предоставлена · предоставлена · проверена |
| `egrn_file` | Присланный файл |
| `gate_remotes` | Сколько пультов выдано |
| `rules_accepted_at` | Когда ознакомился с правилами |
| `onboarding_step` | На каком шаге остановился |

Отдельная таблица `vehicles`: квартира · госномер · марка · примечание.
Пригодится и для пропускной системы, и когда нужно найти владельца машины.

### Что видит председатель

Чек-лист заселения: кто прошёл сценарий, у кого нет выписки ЕГРН, сколько
пультов выдано, какие авто закреплены за квартирами. Это же попадёт во
вкладку веб-кабинета.

## Порядок работ

| Этап | Что делаем | Нужен ли сервер |
|------|-----------|-----------------|
| **A. Сейчас** | Обкатка сбора показаний на жителях, пополнение словаря | Нет |
| **B. Параллельно** | Наполнение базы знаний Домоведа, тестовый режим | Нет |
| **C.** | Модуль задач (только председатель) | Нет |
| **D.** | Перенос на сервер | — |
| **E.** | Вкладка новосёлов + открытие Домоведа жителям | Да |
| **F.** | Веб-кабинет председателя: всё с телефона | Да |

Этапы A, B и C идут на вашем ноутбуке — можно начинать хоть сейчас.
Сервер обязателен там, где системой пользуются жители круглосуточно.
