# Домовед: руководство председателя

Это руководство на случай, когда помощи со стороны нет: подписка закончилась,
интернет не тот, человек, который всё настраивал, недоступен. Здесь собрано
то, что нужно, чтобы дом продолжал работать: как запустить бота, что он делает
сам, где что лежит, как чинить привычные поломки и как ничего не потерять.

Бот живёт на вашем ноутбуке и в Telegram. Он не зависит ни от какой подписки,
кроме интернета: пока ноутбук включён, Домовед принимает показания.

## Если нет времени читать

Все команды выполняются в PowerShell из папки проекта. Открыть её: проводник →
папка с Домоведом → щёлкнуть правой кнопкой на пустом месте → «Открыть в
терминале».

```powershell
git pull                                                            # забрать обновления
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Restart   # перезапустить
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Status    # жив ли бот
notepad .env                                                        # открыть настройки
```

Проверка «бот жив»: напишите ему в личку `/start` — должно прийти меню.

## Что делает бот сам

Ничего из перечисленного запускать руками не нужно — это происходит по
расписанию, пока бот работает.

| Когда | Что |
|---|---|
| 17, 18, 19, 20 числа в 10:00 | напоминание в чат дома — для всех |
| 18 и 19 числа в 20:00 | личные напоминания зарегистрированным, кто ещё не передал |
| 20 числа в 9:00 | ведомость непередавших — вам |
| 20 числа в 14:00 | ведомость за месяц со всеми показаниями |
| 20 числа в 14:30 | реестр ОЭК — вам на проверку |
| 21 числа в 10:00 | реестр ещё раз, на сверку перед отправкой |
| 21 числа в 20:00 | реестр уходит на почту ОЭК |
| 20 числа в 18:00 | объявление в чат, что сбор завершён |
| 23 и 25 числа в 20:00 | напоминания опоздавшим — с другим текстом |
| каждый день в 9:00 | напоминание о задачах председателя из годового плана |

Срок сбора — **с 16 по 20 число, до 12:00**. Ведомость формируется 20-го в
14:00, и эти два часа — запас: показания, пришедшие в 12:30, в неё ещё попадут.
Всё, что позже 14:00, бот примет, но учтёт в следующем расчётном периоде и
предупредит об этом жителя.

Показания принимаются тремя путями: кнопкой «🏠 Передать показания» в боте,
сообщением в чате дома и сообщением боту в личку. В чате бот ставит 👍 — это и
есть подтверждение, подробная квитанция уходит жителю в личку.

## Запуск, перезапуск, остановка

Бот поднимается сам при входе в систему — этим занимается задание
**«DH OS (Домовед)»** в планировщике заданий Windows. Окна у него нет, всё
пишется в журнал `logs/dhos.log`.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Status    # состояние
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Restart   # перезапуск
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Install   # включить автозапуск
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Remove    # выключить автозапуск
```

Вручную, с окном и видимыми сообщениями:

```powershell
python run.py
```

**Один бот на компьютер.** Два процесса на одном токене Telegram не разводит:
сообщения достаются то одному, то другому, и часть показаний теряется. Поэтому
перед ручным запуском остановите автозапуск, иначе бот ответит «Домовед уже
запущен на этом компьютере».

Пока бот работает, он просит Windows не уходить в спящий режим — иначе
показания, присланные днём, повиснут в очереди Telegram до пробуждения. Экран
при этом гаснет как обычно. В настройках Windows действие при закрытии крышки
стоит поставить «Действие не требуется».

## Обновление

После `git pull` бот продолжает работать со старой версией — процесс сам не
перезапускается:

```powershell
git pull
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Restart
```

Памятки читаются из файлов при каждом запуске, новые таблицы в базе создаются
сами. Ничего дополнительно делать не нужно.

## Настройки: файл .env

Это обычный текстовый файл в папке проекта. В проводнике он прячется (имя
начинается с точки), поэтому открывайте из терминала:

```powershell
notepad .env
```

Сохранять — **Файл → Сохранить** (надёжнее, чем Ctrl+S: его легко промахнуть, и
правка не сохранится). Проверить, что записалось:

```powershell
Get-Content .env -Encoding UTF8 | Select-String "READINGS_"
```

После правки — перезапуск бота. Если одна и та же строка встречается дважды,
бот берёт нижнюю; лучше лишнюю удалить.

| Строка | Что задаёт |
|---|---|
| `BOT_TOKEN` | ключ бота в Telegram. **Никому не показывать и не пересылать** — кто им владеет, тот и управляет ботом. Утёк — перевыпустить у @BotFather |
| `ADMIN_IDS` | кто в боте председатель (ваш Telegram ID) |
| `APARTMENTS_COUNT`, `NONRESIDENTIAL_COUNT` | сколько квартир и нежилых помещений в доме |
| `GROUP_CHAT_ID` | чат дома, откуда собираются показания |
| `COUNCIL_CHAT_ID` | чат Совета дома: туда уходит сводка по задачам |
| `CHAT_CONFIRM` | как бот отмечает приём в чате: `auto` (👍, а если реакции запрещены — короткий ответ), `reaction`, `reply`, `off` |
| `PROXY_URL` | локальный порт клиента VPN, если Telegram открывается только через него |
| `READINGS_DAY_START`, `READINGS_DAY_END` | срок сбора: 16 и 20 |
| `READINGS_DEADLINE_HOUR` | до какого часа 20-го ждём показания: 12 |
| `STATEMENT_DAY`, `STATEMENT_HOUR` | когда формируется ведомость: 20-го в 14:00 |
| `REMINDER_DAYS`, `REMINDER_HOUR` | личные напоминания: 18, 19, 23, 25 в 20:00 |
| `CHAT_REMINDER_DAYS`, `CHAT_REMINDER_HOUR` | напоминания в чат: 17, 18, 19, 20 в 10:00 |
| `SELF_REPORTING_FLATS` | квартиры, которые передают показания сами, напрямую ресурснику |
| `SMTP_*`, `MAIL_TO` | почта для отправки реестра ОЭК. `SMTP_PASSWORD` — пароль приложения из почты, не пароль от ящика. `SMTP_HOST` должен совпадать с адресом: `smtp.yandex.ru` для Яндекса |
| `OEK_MAIL_DAY`, `OEK_MAIL_HOUR` | когда реестр уходит в ОЭК: 21 числа в 20:00 |
| `OEK_REVIEW_HOUR` | во сколько в этот день реестр приходит вам на сверку |

Токен и пароль почты хранятся только в этом файле. В переписку, в чат и в
репозиторий они не попадают — файл `.env` нарочно не отправляется на GitHub.

## Ежемесячный круг дел

Почти всё бот делает сам; вам остаются кнопки в «🛠 Меню председателя».

1. **16–20 числа** — следите, как идёт сбор: «📋 Реестр квартир» (кто сдал),
   «🔴 Должники», «📈 Статистика».
2. **Бумажные бланки.** Сфотографируйте заполненный бланк и пришлите боту в
   личку — он спросит номер квартиры и вернёт форму с прошлыми показаниями,
   цифры останется переписать. Сам бот рукописное не читает: ошибка в одной
   цифре уходит в ведомость и находится только через месяц.
3. **20 числа** — ведомость и реестр ОЭК приходят сами: «📄 Ведомость
   передачи», «📨 Реестр ОЭК».
4. **21 числа утром** реестр приходит ещё раз, на сверку, с двумя кнопками.
   Всё верно — ничего не делайте, в 20:00 он уйдёт в ОЭК сам (или нажмите
   «📧 Отправить в ОЭК сейчас»). Нашли ошибку — «⏸ Отложить отправку»,
   исправьте показания и отправьте кнопкой: файл соберётся заново.
   Правила ОЭК к файлу и что с ними делает бот — в
   [oek-reestr.md](oek-reestr.md).
5. **Исправить ошибку.** Кнопка «✏️ Исправить показание» или сообщение боту в
   личку с первой строкой `Исправить за август` и дальше обычным шаблоном.
6. **Счётчики квартиры.** «🔧 Счётчики квартиры» — выбрать квартиру и указать
   2 или 4 прибора воды. История показаний при этом сохраняется.
7. **Акты поверки.** «📄 Акты поверки» — список квартир, приславших акты, и
   готовая строка «кв. 5, 12, 43» для приложения к письму ресурснику.
8. **Вопросы без ответа.** «❓ Вопросы без ответа» — о чём спрашивали жители, а
   памятки нет. По ним и дописываются памятки.

## Резервные копии

Три независимых места — чтобы потеря любого одного ничего не решала.

**0. Переписка с ботом.** Кнопка «🧹 Очистить переписку» в меню председателя
убирает сообщения в чате — свои и ваши, до 300 последних. Telegram разрешает
ботам удалять только то, что не старше 48 часов; остальное уберёт «Очистить
историю» в меню самого чата. На данные это не влияет: показания, ведомости и
памятки лежат в базе на компьютере, а не в переписке.

**1. База показаний.** Кнопка «💾 Резервная копия» в меню председателя:
бот делает копию и присылает её файлом прямо в Телеграм. Копия остаётся и на
ноутбуке, в папке `backups`. Делайте раз в месяц, после сдачи ведомости.

Восстановление: остановить бота, положить файл копии в папку `database` под
именем `dhos.db` (старый файл сперва переименовать), запустить бота.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Remove
copy database\dhos.db database\dhos-старая.db
copy backups\dhos_20261020_141500.db database\dhos.db
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Install
```

**2. Код и документы.** Всё, кроме базы и `.env`, лежит на GitHub в
репозитории `hobuchenie11-create/my-project`. Доступ к нему — по вашей учётной
записи GitHub, она ни от чего другого не зависит. Раз в пару месяцев полезно
скопировать всю папку проекта на флешку: это полный архив с историей правок.

**3. Переписка.** Чаты хранятся в аккаунте сервиса, и это единственное, что
может стать недоступным. В настройках аккаунта есть выгрузка данных (раздел
про конфиденциальность) — архив приходит ссылкой на почту. Поэтому всё важное
мы складываем не в переписку, а в файлы: памятки — в `content/faq/`, письма —
в `docs/letters/`, порядок работы — в это руководство.

## Когда что-то пошло не так

**Бот молчит на всё.** Первым делом — журнал:

```powershell
Get-Content logs\dhos.log -Tail 40 -Encoding UTF8
```

- `Cannot connect to host api.telegram.org` — нет интернета или выключен клиент
  VPN. Включить и перезапустить бота.
- `Не удалось подключиться к прокси … порт закрыт` — клиент VPN сменился, и
  порт в `PROXY_URL` больше не тот. Посмотреть порт в клиенте и поправить
  `.env`; если VPN работает в системном режиме, строку `PROXY_URL` очистить.
- `Домовед уже запущен` — запущено два экземпляра, лишний закрыть.

**Бот не видит показания в чате дома.** В журнале при запуске будет
предупреждение про режим приватности. Лечится у @BotFather: Bot Settings →
Group Privacy → Turn off, затем удалить бота из чата и добавить заново.

**Сообщение «показания не записаны».** Бот всегда пишет причину: номер
квартиры не разобран, показание меньше предыдущего, в одном сообщении
несколько квартир. Жителю это уходит в личку, в чат — только если в личку не
получилось.

**Напоминание жителю не дошло.** Чаще всего `Request timeout` — связь моргнула.
Можно отправить вручную: «🔔 Напомнить должникам».

**Кнопки в телефоне старые.** Меню в Telegram остаётся от прошлого запуска —
отправьте боту `/start`.

## Как править памятки

Памятки — обычные текстовые файлы в папке `content/faq/`, по файлу на тему.
Откройте любой в блокноте, чтобы увидеть устройство: сверху между строк `---`
служебный заголовок, ниже текст, который житель получит в Телеграме.

- `title` — заголовок и подпись кнопки в меню;
- `category` — раздел (список в `database/models.py`, константа `FAQ_CATEGORIES`);
- `keywords` — слова, по которым житель может спросить своими словами: чем
  больше вариантов, тем лучше находится;
- `image` — имя файла из `content/faq/images/`, если к памятке есть плакат;
- `action` — сценарий, который памятка предлагает начать кнопкой;
- `order` — порядок внутри раздела.

В тексте можно выделять `<b>жирным</b>`, списки писать строками с «•». После
правки — перезапуск бота, памятки перечитываются при запуске.

Новая памятка — это просто новый файл в той же папке. Имя файла (латиницей,
без пробелов) становится её кодом, переименовывать потом не стоит.

## Письма ресурсникам

Готовые тексты лежат в `docs/letters/`:

- `vodokanal-reestr.md` — в АО «Омскводоканал»: приём показаний единым реестром
  по электронной почте и ответственный за корректировки;
- `omskrts-reestr-i-akty.md` — в АО «Омск РТС»: то же плюс внесение в базу
  начислений сведений о поверке приборов учёта.

Короткое письмо о корректировке ошибочного показания бот отдаёт кнопкой
«✉️ Письмо в ОмскВодоканал» — тему и текст остаётся вставить в почту и
заполнить прочерки. Ответ жителю о ходе корректировки — кнопка «💬 Ответ
жителю».

Приложения к письму в РТС собираются скриптами (нужны `python-docx`,
`reportlab`, `pillow` — ставятся один раз командой
`pip install python-docx reportlab pillow`):

```powershell
python -m scripts.appendix_list --out Приложение1.docx --pdf Приложение1.pdf --date "08.10.2026 г."
python scripts\attachments.py --images <папка со снимками> --out Приложение2.docx --pdf Приложение2.pdf --date "08.10.2026 г."
```

Состав приложений — списком в начале каждого скрипта: квартира, файл снимка и
подпись под ним. Добавить квартиру — дописать такой же блок.

## Где что лежит

```
run.py                  запуск бота
.env                    настройки, токен, пароли — наружу не отдавать
database/dhos.db        база: квартиры, жители, показания, задачи
backups/                резервные копии базы
logs/dhos.log           журнал: что бот делал и что пошло не так
content/faq/            памятки для жителей (+ images/ — плакаты)
docs/                   это руководство, письма, описание шаблонов
scripts/autostart.ps1   автозапуск Windows
scripts/attachments.py  приложение № 2 к письму (документы по квартирам)
scripts/appendix_list.py приложение № 1 (перечень квартир)
excel/                  ведомости, реестр ОЭК, годовой план
bot/                    сам бот: обработчики, тексты, расписание
```

Если однажды понадобится разобраться глубже — в `README.md` то же самое,
но подробнее и для того, кто читает код.
